# Linkdesk：四分钟演示

## 演示前

运行 `python run_agent.py`，打开 `http://127.0.0.1:8860/`。左下角检查模型连接。首次查证与方法提炼需要真实模型调用，建议先跑完一次并保留记录，现场展示已完成记录并补做一次接管操作。

使用合成案例时明确说明主体和材料是虚构的，但浏览器、模型、工具调用及方法提炼实际运行。不要把固定样例的通过说成生产准确率。

## 0:00–0:40：先讲用户问题

“核验人员已经有一批疑似关系，但最终标签背后的查证方法往往丢失。下一位同事还要重新找材料、核对条件。我想把专家查证时的操作、引用和纠正一起留下来，变成可以用于新案例的方法。”

打开“澄海游戏 × 云帆营销”。指出同 IP、同 App 只是候选线索。

## 0:40–1:30：让 Agent 做查证，专家能接管

点击“开始查证”。右侧展示 Agent 实际打开的材料。

“模型选择下一步查什么，浏览器执行操作；左侧是对话，右侧保留实际网页。我可以暂停，自己打开其他材料，也可以引用原文告诉它这段证据支持什么。”

点击“暂停并接管”，打开原文，选中一句授权范围，点击“引用所选原文”。补充：

> 这份授权只支持广告代理执行，不证明集团控制或最终预算决策。

然后在对话里要求它继续核验并修正草稿。先暂停再接管，避免与 Agent 同时操作一个页面。

## 1:30–2:10：结果不是单一的合并按钮

打开“核验结果”。

“代理关系可被这份有效授权支持，但集团和预算仍未知。每个标签有自己的证据，点击能回到原文。系统先检查引用，再独立检查材料能不能支持这个标签；最后由专家确认。”

填确认依据，点击“确认本案标签”。

## 2:10–3:00：专家判断成为候选 Skill

点击“提炼查证方法”，切到“查证方法”。

“这里留下的是核对主体、范围、日期以及遇到冲突怎么处理的方法。它是模型根据本案实际记录生成的候选稿，我可以直接编辑，不把一次操作自动当成正确 SOP。”

检查停止条件里是否包括授权过期和证据不足。确认启用，选择“用于新案例”。

## 3:00–4:00：换主体，再换反例

先展示“星原科技 × 微澜互动”应用方法后的新案结果，打开引文说明来源属于新主体。

再展示“北川科技 × 远山传媒”：授权已经过期，应保留当前代理关系未知。

“同一个方法可以复用，但结论必须跟着新证据变化。过期只能说明材料不足，不能反过来证明没有代理关系。集团与代理还可能同时存在，第四个案例验证这个边界。”

## 遇到追问

**是不是录屏转 SOP？**

记录工具、网页快照、引文与专家明确的解释。截图用于重看页面，不能单独证明专家为什么判断。

**是不是训练了模型？**

没有。当前将经确认的方法作为运行时 Skill 加入上下文，新案仍取新证据。是否值得微调，需要更多稳定标注和评测后决定。

**为什么会节省专家时间？**

目标是让专家少做重复找资料、整理依据的工作，将时间集中在缺口和冲突。尚未测出真实节省比例，需要把核对、纠错、返工的时间一并计入对照实验。

**普通 Agent 本来也知道这些规则，Skill 有用吗？**

这版验证了方法的提炼、版本和执行链路，尚未证明准确率增益。下一步需对照无 Skill 的基础 Agent，用未参与提炼的业务案例验证方法是否提高合格产出、降低专家耗时。
