# Linkdesk Agent 工作区：产品设计

## 用户与任务

核验人员与业务专家需要判断两家公司究竟是什么关系。候选关系可能来自共享 IP、共同投放 App、联系人或其他线索；这些信号用于发现问题，不能直接充当集团控制的证据。

本产品聚焦候选生成之后的一段工作：查询材料、组织证据、修正标签、确认判断，并保存下一次可复用的查证方法。

## 核心取舍

| 问题 | 选择 | 原因 |
|---|---|---|
| 先搭复杂表单，还是直接协作查证？ | Agent 对话为主，浏览器与结果在旁边 | 专家能够在查证当下补充判断，不必事后重写 SOP |
| 记录什么？ | 工具参数、页面快照、引用、明确纠正、最终确认 | 点击坐标与浏览时长不能说明证据支持什么 |
| 如何沉淀方法？ | 已确认案例 → 候选 Skill → 专家编辑启用 | 一次操作记录不自动成为正确方法 |
| 如何复用？ | 把方法加入新案 Agent 上下文，重新取证 | 保留查证顺序与边界，不携带旧公司结论 |
| 证据不足怎么办？ | 各关系维度独立保留未知 | 预算缺证据不应阻止代理关系先完成确认 |

## 交互

1. 从合成案例或自建核验进入，给出问题与来源。
2. Agent 选择工具，右侧同步显示浏览器。专家可暂停后浏览、选中原文并注明它支持或排除什么。
3. Agent 生成集团、代理、预算三个维度的草稿，引用可回到保存的原文。
4. 专家在对话中纠正，或确认本案结果。修订草稿会让旧确认失效。
5. 提炼候选方法；专家编辑步骤、适用条件、验收条件和停止条件，再用于下一案。

界面默认显示用户动作与判断，不要求用户理解工具 JSON。完整过程留在“过程记录”中，供需要时追溯。

## 候选 Skill 的内容

- 解决什么问题、适用哪些情况。
- 查询顺序、应寻找的证据和核对步骤。
- 主体、日期、授权范围等验收条件。
- 缺证据、冲突或过期时停止或转人工的条件。
- 禁止推导的结论，以及哪条专家纠正被吸收。

Skill 是运行时指令，不是模型训练结果。一个方法能运行，不代表方法有效；是否值得保留，要用独立案例与人工时间衡量。

## 如何验证价值

暂不声称节省了多少时间或提高了多少准确率。产品试点可使用以下口径：

| 指标 | 口径 |
|---|---|
| 合格标签产出率 | 抽样复核通过的已确认标签 / 已确认标签 |
| 每条合格标签的专家耗时 | 阅读、核对、纠正和返工总时间 / 合格标签数 |
| 建议采用率 | 专家实际确认的建议数 / 专家查看且可处理的建议数；原样采纳与修改后采纳分开 |
| 方法持续复用 | 启用方法后，在后续适用案例中再次使用的人数及次数 |
| 错误确认率 | 被确认但后续证实错误的标签 / 被复核标签；关注高影响错误 |

验证应按案例难度分层，比较人工基线、普通 Agent 与使用 Skill 的 Agent，采用未参与提炼的新案例。不能把查看页面、点击启用或完成模型调用计作业务采纳。

## 当前范围

公开网页、用户主动上传的文字材料、单用户本机存储、人工确认。未实现企业 CRM 回写、企业账号权限、跨团队审批或生产队列调度。
