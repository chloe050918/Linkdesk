THE PROBLEM

模型能给出候选，
谁来判断它是否可信？

两个公司用同一个 IP、推同一个 App，可能同属集团，也可能只是共同使用一家代理商。专家需要读材料、找差异、补充事实，再确认关系。

当候选关系越来越多，瓶颈就变成：哪些案例值得先看？相同的核验方法，为什么要反复从头解释？

复用检查方法，
让每个结论仍然依靠自己的证据。

ONE COMPLETE WORKFLOW

从有限名额，到可复用的核验经验。

01

先安排值得看的案例

冲突、高影响关系、重复模式代表优先；为未优先处理的案例保留随机抽检。

02

对照差异，核验代表

六项相似信号，授权却有有效、过期和缺失之分。专家确认具体关系与范围。

03

验证规则的适用边界

从已复核来源建立模板，先检查十个固定合成边界场景，再决定是否启用。

04

逐案准备下一轮草稿

每份草稿引用自己的材料。不适用项保留原因，最终仍需人工确认。

EVIDENCE, NOT SIMILARITY

同类问题，
可以有不同答案。

代理合作与集团关系可能同时成立。保留这个反例，才能避免把一次正确判断变成一批错误标签。

BUILT & TESTABLE

流程真实运行，
能力边界也明确。

  • 安排、材料、复核、档案和模板保存在 SQLite；刷新后仍可继续。
  • 默认使用保守的本地提取规则。可选模型适配器尚未验通真实在线服务。
  • 模板只生成待确认草稿，不自动合并客户，不写入真实业务系统。
  • 固定回归验证规则边界；没有宣称线上准确率或节省工时。

RUN LOCALLY

一个命令，打开完整工作区。

python3 server.py --port 8850

Python 3.9+ · 无第三方运行时依赖 · 本机保存
